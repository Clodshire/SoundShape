# "코드는 어떻게 했나요?" 대응

심사위원이 코드를 물을 때는 보통 셋 중 하나입니다. **어느 쪽인지 먼저 가려내십시오.**

| 질문 | 진짜 묻는 것 |
|---|---|
| "코드 좀 볼 수 있나요?" | 진짜로 있긴 한가 |
| "이거 다 직접 짰나요?" | 어디까지가 네 것인가 |
| "뭘 썼나요?" | 기술 스택 |

---

# 1. "직접 짰나요?" — 제일 자주 나옵니다

가져온 것과 만든 것을 **먼저 갈라 놓고** 시작하십시오. 숨기려다 들키면 나머지가 다 의심받습니다.

> **모델은 공개된 걸 가져다 썼습니다. 그 모델들을 이어 붙여서 하나의 흐름으로
> 만든 것, 그리고 감정을 판단하는 분류기는 저희가 만들었습니다.**

그다음 숫자를 대십시오. **직접 센 것들입니다.**

| | |
|---|---|
| 파이썬 | **37개 파일 · 5,617줄** |
| 타입스크립트 (웹·확장) | **38개 파일 · 8,238줄** |
| 보조 스크립트 (학습·평가·렌더) | **24개** |
| 자동화 테스트 | **112개 전부 통과** |
| 커밋 | **100개** |

> 라이브러리 코드는 뺀 숫자입니다. 모델은 가져다 썼지만 **그 모델들이 혼자서는
> 아무것도 못 합니다** — 어디서 자를지, 뭘 잴지, 뭘 믿고 뭘 버릴지는 전부
> 저희가 정해서 짠 겁니다.

---

# 2. 포스터 단계별로 뭘 썼나

포스터 ③의 흐름 그대로입니다. **왼쪽에서 오른쪽으로 읽으면 그게 실제 실행 순서입니다.**

| # | 포스터 단계 | 쓴 프로그램 | 출처 | 우리가 한 일 |
|---|---|---|---|---|
| 0 | 영상에서 소리 꺼내기 | **FFmpeg** · soundfile · librosa | 오픈소스 | 16kHz 모노로 통일 (`audio_io.py`) |
| 1 | **음원 분리** | **HDemucs** | torchaudio 기본 번들 | 목소리만 남기고 나머지 버림 (`separation.py`) |
| 2 | 말 단위로 자르기 | **Whisper** (faster-whisper) + **Silero VAD** | 오픈소스 · VAD 는 Whisper 내장 | 발화 단위로 분할 (`asr.py`, `chunker.py`) |
| 3 | **운율 측정** | **PRAAT** (parselmouth) | 음성학 표준 도구 | **14가지 수치**를 직접 골라 추출 (`prosody.py`) |
| 4 | 목소리를 숫자로 | **wav2vec 2.0** 3종 | HuggingFace | 언어별로 갈라 쓰도록 라우팅 (`emotion.py`) |
| 5 | **감정 판단** | **scikit-learn** (선형 SVM) | 라이브러리 | **저희가 학습시킨 모델** (`trained_classifier.py`) |
| 6 | 글자 뜻 보조 | DistilBERT · KoBERT 계열 | HuggingFace | 말투가 애매할 때만 참고 (`text_sentiment.py`) |
| 7 | **도형 그리기** | **WebGL 셰이더** | 직접 작성 | 감정 → 색·모양·움직임 변환 (`emotionField.ts`, `mapping.ts`) |
| 8 | 손목 진동 | **Web Serial** + Arduino | 브라우저 API | 감정별 리듬 설계 (`haptic.ts`) |

**굵은 것이 포스터에 그림으로 들어간 단계**입니다.

# 3. 한 문장씩 이어서 설명하기

실제 데이터가 흘러가는 순서입니다. **이 순서대로 말하면 막히지 않습니다.**

**① 소리를 꺼냅니다.** 영상에서 FFmpeg 으로 오디오를 뽑아 16kHz 모노로 통일합니다.
모든 뒤 단계가 같은 형식을 기대하기 때문입니다.

**② 목소리만 남깁니다.** HDemucs 가 음악·효과음·목소리를 분리합니다. 이걸 안 하면
배경음악의 음높이를 목소리로 착각합니다. torchaudio 에 기본 포함된 모델이라
따로 받으러 다니지 않았습니다.

**③ 말 단위로 자릅니다.** Whisper 가 글자로 받아쓰면서 **단어 하나하나의 시각**을
알려 줍니다. 그걸로 발화 단위를 끊습니다. 원본 대신 faster-whisper 로 돌리는데,
CPU 에서 4배 빨라서 노트북 시연이 가능해집니다. 무음은 내장 Silero VAD 가 걸러냅니다.

**④ 운율을 잽니다.** 각 구간에 PRAAT 을 돌려 **14가지**를 꺼냅니다 — 음높이
5가지(평균·표준편차·최저·최고·범위), 세기 4가지, 떨림 2가지(jitter·shimmer),
잡음비, 유성음 비율, 말 속도. **여기는 추측이 아니라 측정입니다.**

**⑤ 목소리를 숫자로 바꿉니다.** wav2vec 2.0 이 목소리를 **1024개 숫자**로 바꿉니다.
영어는 audeering, 한국어는 XLSR-korean 을 씁니다.

**⑥ 감정을 정합니다.** 1024개 + 14개 = **1,038개 숫자**를 저희 분류기에 넣습니다.
표준화 → PCA → 선형 SVM. 7가지 감정에 점수를 매기고 제일 높은 걸 고릅니다.
그 점수가 확신도입니다.

**⑦ 글자는 보조로만 봅니다.** 말투의 긍부정이 0에 가까워 판단이 안 설 때만
글자 뜻을 참고합니다. 말투가 분명히 부정이면 글자가 긍정이어도 무시합니다 —
**비꼼이 살아남는 규칙이 이것입니다.**

**⑧ 그립니다.** 감정과 운율을 색·모양·움직임으로 바꿔 WebGL 로 그립니다.
색과 모양은 분류기가 정하고, **크기·채도·움직임은 ④에서 잰 값이 직접 정합니다.**
그래서 AI 가 감정 종류를 틀려도 세기와 떨림은 바르게 남습니다.

**⑨ 손목으로 보냅니다.** 같은 값을 Web Serial 로 밴드에 보냅니다. 감정마다 리듬이
다르고, 세기는 지금 나는 목소리 크기를 곱합니다.

# 4. 어디서 구했나

| 가져온 것 | 어디서 | 왜 그걸 골랐나 |
|---|---|---|
| HDemucs | **torchaudio 기본 번들** | 추가 설치 없이 바로 쓸 수 있음 |
| Whisper large-v3-turbo | 오픈소스 (faster-whisper 로 실행) | 한국어가 강하고, CTranslate2 로 CPU 4배 |
| Silero VAD | **faster-whisper 내장** | 따로 설치한 게 아님 |
| wav2vec2 3종 | **HuggingFace** | ④ 참조 |
| DistilBERT · 한국어 BERT | **HuggingFace** | 다국어 모델이 한국어를 틀려서 분기 |
| PRAAT | parselmouth (파이썬 바인딩) | **음성학의 표준 도구** — 논문에서 쓰는 그것 |
| scikit-learn | 라이브러리 | SVM 구현 |
| AIHub 한국어 19,374건 | **AIHub** | 학습 데이터 |
| RAVDESS 영어 1,440건 | 공개 데이터셋 | 학습 데이터 |

**wav2vec2 세 개를 왜 골랐는지**는 따로 물어볼 수 있습니다.

- `superb/wav2vec2-base-superb-er` — 기준점. 그대로 쓰니 한국어 17.5%
- `audeering/...-msp-dim` — 영어 임베딩. 실제 대화로 미세조정된 모델
- `kresnik/wav2vec2-large-xlsr-korean` — **한국어 임베딩. 실험으로 찾았습니다.**
  백본만 바꿔 끼우며 비교했고, 이걸로 바꾸자 17.5% → 49.6%

# 5. "코드 좀 볼 수 있나요?"

**노트북에서 VS Code 를 열지 마십시오.** 대신 셋 중 하나입니다.

1. **깃허브 페이지** — `github.com/Clodshire/SoundShape`.
   ⚠️ 인터넷이 필요하므로 **발표장 오기 전에 탭으로 미리 열어 두십시오.**
2. **터미널에서 `git log --oneline | head -30`** — 100개 커밋이 날짜순으로 나옵니다
3. **폴더를 Finder 로 열기** — 구조만 보여 주기

제일 좋은 건 **1번을 미리 열어 둔 탭**입니다. 커밋 하나하나에 "왜 이렇게 했는지"가
적혀 있어서, 그게 코드 자체보다 설득력이 있습니다.

# 6. 이어서 나올 질문

**"AI 가 코드를 짜 준 거 아닌가요?"**

> 도구는 썼습니다. 다만 **무엇을 만들지, 어떤 순서로 이을지, 어디서 틀리는지는
> 저희가 정했습니다.** 예를 들어 짧은 발화에서 모델이 12개 중 1개만 맞힌다는 걸
> 찾아낸 것, 한국어 백본을 바꿔서 17.5%를 49.6%로 올린 것, 손목은 세기 하나로는
> 감정을 구분할 수 없어서 리듬으로 바꾼 것 — 이건 코드가 아니라 판단입니다.

**"테스트는 어떻게 했나요?"**

> 자동화 테스트 112개가 전부 통과합니다. 무음 파일, 손상된 파일, 모델이 없는
> 경우까지 넣어서 **프로그램이 멈추지 않는지** 봅니다. 그리고 파이썬과
> 자바스크립트가 **같은 입력에 같은 그림을 그리는지** 바이트 단위로 비교하는
> 테스트도 있습니다 — 웹과 확장이 다르게 보이면 안 되니까요.

**"혼자 했나요?"**

사실대로. 팀 구성과 역할 분담을 그대로 말하면 됩니다.

**"어디가 제일 어려웠나요?"** — 이건 기회입니다. 하나만 고르십시오.

> 한국어였습니다. 영어로는 되던 게 한국어에서는 17.5%, 거의 찍기 수준이었습니다.
> 모델을 바꿔 보고, 데이터를 바꿔 보고, 결국 **한국어 전용 임베딩으로 갈아 끼우는
> 게 답**이라는 걸 실험으로 찾았습니다. 49.6%까지 올렸지만 아직 절반입니다.
