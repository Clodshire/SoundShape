# Ⅱ. 작품 제작

## 1. 작품 설계

### 목표
본 작품 **SoundShape**는 음성의 운율과 인공지능을 이용해 화자의 감정을 추출하고, 이를 시각 언어로 번역해 영상 위에 자막과 함께 보여 주는 시스템이다. 설계의 목표는 크게 네 가지다. 첫째, 음성 입력에서 시각 출력까지 한 줄로 이어지는 **실제 작동하는 end-to-end 시스템**을 만든다. 둘째, *"왜 분노가 빨강인가"* 라는 물음에 답할 수 있도록 모든 시각 규칙을 **연구에 근거**하게 한다. 셋째, 처음 본 사람도 5초 안에 이해하는 **직관적이고 아름다운** 시각화를 구현한다. 넷째, 주 사용 언어인 **한국어를 지원**한다.

### 작동 원리
SoundShape는 음성을 다음 단계로 처리한다. **〔그림 1〕 전체 처리 파이프라인** 참조.

1) **음성 정규화:** FFmpeg를 사용해 입력 음성·영상을 **16kHz 단일 채널 WAV**로 변환한다. 이는 이후 모든 분석 모델이 요구하는 표준 형식이다.
2) **자막 생성:** OpenAI Whisper(faster-whisper, large-v3-turbo)로 발화를 **글자와 단어 단위 타임스탬프**로 변환한다. 침묵 구간을 기준으로 음성을 나누어, 발화 단위로 처리한다.
3) **운율 추출:** 각 발화 구간에서 Parselmouth(PRAAT)로 **음높이(F0)·세기·지터·시머·발화 속도 등 15종의 운율 특징**을 추출한다. 이는 사람이 해석할 수 있는 *명시적* 단서다.
4) **감정 분류:** wav2vec2 기반 두 모델을 사용한다. **범주형**(분노/기쁨/중립/슬픔)과 **차원형**(정서가·각성·우월성의 연속값)이다.
5) **감정 결정(보정·하이브리드):** 차원형 모델의 *계통적 편향*을 데이터 기반으로 **보정**하고, 범주형과 차원형을 결합한 **하이브리드**로 최종 감정을 정한다(범주형이 약한 부분을 차원형이 보완). 한국어는 **텍스트 감성**으로 정서가를 *보조*하되, 말투가 분명히 부정적이면 무시해 **비꼼을 보존**한다. 모델의 확신이 낮으면 시각을 **중립화**한다.
6) **운율 변조:** *측정된* 지터·시머는 시각의 **떨림 진폭**을, 강도는 **크기**를, 발화 속도는 **움직임 속도**를 직접 조절한다. 따라서 같은 감정으로 분류된 두 음성도 더 떨리거나 크면 다르게 보인다.
7) **시각 매핑:** 감정을 **도형·색·크기·움직임**으로 번역한다(**〔그림 2〕 감정→시각 매핑** 참조). 규칙은 연구에 근거하며(아래 표), **하나의 설정(config)**에 정의되어 백엔드와 프론트엔드가 동일하게 읽는다.
8) **시각화 출력:** WebGL 셰이더로 감정 에너지 필드를 영상 위에 오버레이하고 자막과 동기화한다. 첫 구간을 짧게 처리해 **약 6초 만에 재생을 시작**하고, 이후를 재생보다 앞서 처리해 **재생 중 지연을 0**으로 만든다.

**감정→시각 매핑의 근거**

| 채널 | 규칙 | 근거 |
|---|---|---|
| **도형** | 각진=위협, 둥근=따뜻 | Aronoff(1992); Bar & Neta(2006, 편도체) |
| **색(색상)** | 분노=빨강 등(범문화적) | Hupka(1997) |
| **색(채도·명도)** | 채도∝각성, 명도∝정서가 | Valdez & Mehrabian(1994) |
| **크기** | ∝각성, 저음=큼 | Russell(1980); Ohala(1994) |
| **움직임** | 빠르고 거친=분노/고각성 | Pollick(2001); Banse & Scherer(1996) |

### 작품 설계
SoundShape는 **클라이언트–서버 구조**다(**〔그림 3〕 시스템 구성** 참조). 사용자는 **웹 애플리케이션**(파일 업로드·유튜브 링크)이나 **크롬 확장 프로그램**(유튜브 위 실시간 오버레이)으로 접근하며, 무거운 분석은 **백엔드 서버**(FastAPI)가 담당한다. 매핑 규칙을 단일 설정으로 외부화하여, 백엔드(Python)와 프론트엔드(TypeScript)가 *동일한 규칙*을 읽고 **출력이 바이트 단위로 같음**을 자동 검증한다.

## 2. 작품 제작

| 제작 항목 | 내용 | 결과 이미지 |
|---|---|---|
| **백엔드 파이프라인** | FFmpeg·Whisper·PRAAT·wav2vec2를 연결해, 발화 구간마다 자막·운율·감정을 추출하고 **JSON 타임라인**으로 만든다. | 〔이미지: JSON 타임라인 출력〕 |
| **감정 매핑 엔진** | 설정(config) 기반으로 감정을 시각으로 번역한다. 운율 변조·불확실성 중립화를 포함하며, **Python·TS 동일성**을 검증한다. | 〔이미지: 매핑 도식/코드〕 |
| **시각화(WebGL)** | 프랙탈 노이즈로 분위기적 에너지 필드를 만들고 감정별 실루엣에 가둔다(OLED 배경화면 같은 미감). | 〔이미지: 감정별 시각화〕 |
| **웹 애플리케이션** | 파일·유튜브 입력, 자막/시각화 토글, 감정 타임라인, **실시간 스트리밍 재생**. | 〔이미지: 웹앱 화면〕 |
| **크롬 확장 프로그램** | 실제 유튜브 영상 위에 감정 필드를 실시간 오버레이. | 〔이미지: 유튜브 오버레이〕 |
| **정확도 개선** | 차원형 보정 + 하이브리드 + 학습형 분류기로 감정 인식 정확도를 높였다(영어 55→80%, 한국어 17.5→43.6%). | 〔이미지: 혼동행렬〕 |
| **자동화 테스트** | 핵심 로직과 실패 케이스를 검증하는 **23개 자동화 테스트**(pytest). | 〔이미지: 테스트 통과 화면〕 |
