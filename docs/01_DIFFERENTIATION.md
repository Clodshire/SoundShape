# 01. 기존 솔루션과의 차별화

> SoundShape는 어디에 위치하는가, 무엇이 다른가, "그거 이미 X에 있지 않나?"에 어떻게 답하는가.

---

## 1. 기존 솔루션 지도

청각장애인용 또는 음성-시각화 관련 기존 솔루션은 6개 카테고리로 나뉜다.

### A. 표준 자막 시스템 (Standard Captioning)

- **YouTube 자동자막 / Netflix CC / Disney+ 자막**
- **Google Live Caption / Apple Live Captions**
- **국내 KBS·MBC closed caption**

**무엇을 하는가:** 음성을 텍스트로 변환해 화면 하단에 표시.

**한계:**
- *말의 내용*만 전달. *감정·톤·연기*는 전달 못 함
- 비꼼, 진심, 슬픔을 누름 같은 prosodic meaning이 사라짐
- 가끔 `[웃음]` `(속삭이며)` 같은 텍스트 태그가 있지만 **이산적(discrete)** 이고 **드물게** 등장

### B. 환경음 알림 시스템 (Sound Alert)

- **Visualfy** (스페인) — 초인종, 알람, 화재경보 같은 환경음을 시각·진동으로 알림
- **Apple Sound Recognition** — iOS 내장, 알람·울음·물소리 등 감지
- **VibeAware** — 햅틱 피드백 기반
- **국내: 한국전자통신연구원(ETRI) 환경음 인식 기술**

**무엇을 하는가:** 위험·중요 환경음을 *알려준다*.

**한계:**
- *음성*이 아니라 *환경음* 대상
- *알림(notification)* 수준이지 *감정 표현*이 아님

### C. 수어 통역 / 자동 수어 생성

- **SignAll** (헝가리) — 영어→ASL 자동 통역
- **KinTrans** (미국) — AI 수어 인식
- **국내: 한국수어연구회 기술 시연**
- **카카오 i 통역 — 수어 일부 지원 연구**

**무엇을 하는가:** 음성·텍스트를 수어 동작으로 변환.

**한계:**
- *대사 번역*이지 *prosody/감정 전달*이 아님
- 수어 자체가 표정·동작으로 감정을 *어느 정도* 표현하지만, 자동 시스템은 그 깊이까지 도달 못함
- 청각장애인이 *영상 매체*를 볼 때의 격차를 직접 해결하지 않음

### D. 음악 시각화 (Music Visualization)

- **Spotify Visualizer / Apple Music — 음악 시각화**
- **Winamp 류의 클래식 비주얼라이저**
- **Milkdrop, projectM**

**무엇을 하는가:** 음악의 주파수·박자에 반응하는 추상 그래픽 생성.

**한계:**
- *음악 전체*의 분위기에 반응. *발화 단위의 감정*은 분석 못 함
- 미적 효과가 목표이지 *접근성*이 목표가 아님
- 가사·자막과 연동 없음

### E. 감정 자막 연구 (Emotive Captioning Research)

학계와 일부 시제품 단계의 연구들:

- **"SubLeFt: Emotion-Enhanced Subtitles"** — 감정 태그를 자막에 추가하는 연구
- **LG의 Sound-Adapter 시제품** (2021) — 자막 옆 이모티콘 형태로 감정 표시
- **HCI 학회의 "expressive captions" 다수 논문** (CHI, ASSETS)
- **MIT Media Lab의 "Vibrant Captions"** — 텍스트 자체의 폰트·색·크기를 감정에 따라 변경

**한계:**
- 대부분 *시제품/논문 단계*, 상용화·배포 안 됨
- *이산적 emotion tag* (행복/슬픔/분노 등 6~7개 범주) 위주 — 미세한 감정 변화 표현 못 함
- *텍스트 폰트 변형* 중심 — **별도의 시각 언어**를 만든 게 아님
- *음성 prosody*가 아닌 *텍스트 sentiment*에 기반한 경우 많음

### F. 음성 신호 시각화 (Phonetic Visualization)

- **PRAAT 자체** — 음성학 연구자용 도구, 일반 사용자용 아님
- **Wavesurfer.js** — 음성 파형 표시 라이브러리
- **Speech Analyzer (SIL)** — 언어학 분석 도구

**무엇을 하는가:** 음성을 그래프(피치 곡선, 스펙트로그램 등)로 표시.

**한계:**
- *전문가용*. 일반인이 보고 *감정*을 읽어내지 못함
- *접근성 제품*이 아님

## 3. SoundShape의 5가지 핵심 차별화

### 차별화 1: **Prosody-grounded** (음성학 기반)

기존 감정 자막 연구는 대부분 *텍스트 sentiment*(문장의 단어들이 긍정인지 부정인지)를 기반으로 한다. 예: "그래 잘했어"라는 텍스트는 sentiment 분석상 *긍정*으로 보인다. 하지만 비꼬는 톤이면 *실제 감정*은 *negative*다.

SoundShape는 **텍스트가 아니라 음성 신호 자체**(피치 곡선, 강도 변동, jitter, shimmer 등)를 분석하기 때문에 **비꼼·진심·억제된 감정** 같은 *prosodic meaning*을 잡아낼 수 있다.

### 차별화 2: **연속적 감정 표현** (Continuous, not Discrete)

기존 감정 자막은 행복/슬픔/분노/공포/혐오/놀람 같은 *6~7개 이산 카테고리*로 분류한다. 그러나 실제 감정은 *연속적*이며 동시에 여러 감정이 섞인다.

SoundShape는 **Russell의 Circumplex Model (valence × arousal 2D 연속 공간)** 위에 감정을 좌표로 표현한다. 같은 "슬픔"이라도 *차분한 슬픔* vs *격앙된 슬픔*이 다른 시각 표현을 받는다.

### 차별화 3: **다차원 시각 언어** (Multi-dimensional Visual Encoding)

기존 시제품들은 감정을 *하나의 이모지*나 *폰트 색깔* 정도로 표현한다. SoundShape는 **4가지 시각 채널**을 동시에 사용:

| 시각 채널 | 인코딩하는 정보 |
|---|---|
| **모양 (Shape)** | 감정 카테고리 (날카로움/둥글음) |
| **색 (Color)** | Valence (긍정-부정) |
| **크기 (Size)** | Arousal (감정 강도) |
| **움직임 (Motion)** | Stability (안정-동요) |

이런 다채널 인코딩은 *한 번에 풍부한 감정 정보*를 전달한다.

### 차별화 4: **연구 기반 매핑** (Research-Grounded Mapping)

"왜 분노는 빨간색인가? 왜 슬픔은 파란색인가?"

기존 제품은 *임의의 매핑*을 사용한다. SoundShape의 매핑 규칙은 다음 cross-modal correspondence 연구에 근거를 둔다:

- **Hupka et al. (1997)** — 색-감정 매핑의 cross-cultural 연구
- **Spence (2011)** — Crossmodal Correspondences: A Tutorial Review
- **Köhler (1929) / Ramachandran & Hubbard (2001)** — Bouba/Kiki effect (둥근 모양 = 부드러운 소리, 날카로운 모양 = 날카로운 소리)
- **Schubert (2004)** — Music & color associations
- **Russell (1980)** — Circumplex Model of Affect

매핑이 *임의*가 아니라 *과학적 근거*가 있다는 것은 ISEF·KCF 심사에서 강한 어필이 된다.

### 차별화 5: **청각장애인을 메인 타겟으로** (Accessibility-First Design)

기존 음성 시각화는 *음성학자용* 또는 *음악 감상용*이지 *청각장애인이 영화/드라마를 더 풍부하게 누리기 위함*이 아니었다. SoundShape는 **처음부터 청각장애인의 *문화적 향유권*을 위해 설계**된 첫 도구다.

이는 단순한 마케팅이 아니라 *디자인 결정*에 직접 영향을 준다:
- 자막과 *나란히* 배치 (대체가 아닌 보완)
- *직관적으로* 학습 가능한 시각 언어
- 실제 청각장애인 user testing 기반 반복 개선
- 한국 농인 사회의 *문화 콘텐츠 접근* 우선

## 4. 예상 질문 방어

심사위원이 던질 만한 "그거 이미 X에 있지 않나?" 질문에 대한 답변.

### Q1. "YouTube의 `[웃음]` `(슬프게)` 같은 자막 태그랑 뭐가 달라요?"

**A:** 그건 *이산적·드물게* 등장하고 *수동으로 작성*한다. SoundShape는 *연속적·자동으로* 모든 발화의 prosody를 실시간 시각화한다. 또한 *텍스트가 아닌 도형*이라 한눈에 감정을 읽을 수 있다.

### Q2. "Spotify 비주얼라이저 같은 거 아니에요?"

**A:** 비주얼라이저는 음악의 *주파수·박자*에 반응하지 *감정 의미*는 모른다. 같은 비트의 슬픈 곡과 신나는 곡이 비슷한 그래픽을 만든다. SoundShape는 *감정을* 분석한다.

### Q3. "그냥 감정 인식 AI 위에 색깔 입힌 거 아니에요?"

**A:** (a) 단순 카테고리 분류가 아닌 *연속 valence-arousal 공간*에 매핑하고, (b) 시각 언어가 *4채널 다차원*이며, (c) 매핑이 *cross-modal correspondence 연구* 기반이며, (d) *prosody 기반*이지 *텍스트 sentiment* 기반이 아니다. 이 네 가지가 모두 결합된 도구는 시장·학계에 없다.

### Q4. "수어 통역이 이미 감정 전달하지 않나요?"

**A:** 수어는 *표정·동작*으로 감정을 전달할 수 있다. 하지만 (a) *자동 수어 생성*은 그 깊이까지 도달 못함, (b) 청각장애인 중 수어가 *제1언어*가 아닌 사람도 많음 (구어 한국어 기반 농인 등), (c) *영상 콘텐츠 위에 자막을 봐야* 하는 상황에서 수어는 화면을 가린다. SoundShape는 *영상 위에 직접 overlay*되어 영상 시청 흐름을 끊지 않는다.

### Q5. "PRAAT 자체가 이미 음성을 시각화하지 않나요?"

**A:** PRAAT은 *음성학 전문가용* 분석 도구다. 일반인이 PRAAT의 피치 곡선을 보고 *감정*을 읽어낼 수 없다. SoundShape는 PRAAT의 *원자료*를 *비전공자가 직관적으로 이해 가능한 시각 언어*로 *번역*한다. 즉, **PRAAT은 SoundShape의 *재료*이지 *결과물*이 아니다.**

### Q6. "ISEF/KCF에서 비슷한 게 나온 적 있나요?"

**A:** *Captioning* 프로젝트나 *emotion classification* 프로젝트는 여러 번 나왔다. 그러나 (a) *prosody 기반* + (b) *연속 감정 공간* + (c) *cross-modal correspondence 연구 grounding* + (d) *다채널 시각 언어* + (e) *청각장애인 문화 접근성* 이 다섯 가지를 결합한 프로젝트는 본 적이 없다. 이 결합 자체가 SoundShape의 contribution이다.

## 5. 한 줄 차별화 요약

> **기존 솔루션들은 "무엇을 말했는가" 또는 "어떤 소리인가"를 보여준다.**
> **SoundShape는 "어떻게 말했는가" — 즉 *감정의 결*을 보여준다.**
