## ④ 하이브리드 vs AI 전용 비교 — 10분

**목표**: 같은 순간을 두 모드로 찍어 나란히 놓은 한 장.

### 1. 준비

두 서버가 떠 있어야 합니다.

```bash
curl -s -o /dev/null -w "frontend %{http_code}\nbackend  " http://localhost:3000/ && curl -s -o /dev/null -w "%{http_code}\n" http://localhost:8000/docs
```

둘 다 `200` 이 아니면 저에게 말씀하세요. 다시 켜 드리겠습니다.

### 2. 크롬에서 열고 파일 분석

**반드시 크롬입니다.** `http://localhost:3000` → `data/samples/ko_test.wav` 를 끌어다 놓기.
분석이 끝나면 하단에 감정 타임라인(joy / sadness)이 뜹니다.

### 3. 좋은 순간 고르기

두 모드 차이가 큰 지점을 골라야 합니다. **타임라인을 클릭해 재생 위치를 옮기면서**
`렌더링 하이브리드 / AI 전용` 스위치를 눌러 보세요.

- 차이가 잘 보이는 곳: **소리가 큰 구간** (파형 높이·채도가 확 달라집니다)
- 차이가 거의 없는 곳: 조용한 구간 — 여기서 찍으면 그림이 아무 말도 못 합니다
- `ko_test.wav` 기준 **t ≈ 2.0초** ("정말" 부분)에서 확인됨

> 💡 `분석 정보` 토글을 켜 두면 화면 아래에 각성도·채도 수치가 같이 보여서
> 어느 지점이 차이가 큰지 판단하기 쉽습니다. **찍을 때는 다시 끄세요.**

### 4. 스크립트 실행

**크롬 창을 화면 맨 앞에 두세요.** 뒤에 있으면 브라우저가 그리기를 멈춰서 캡처가 비어 버립니다.

`F12` → **Console** 탭 → `frontend/scripts/capture_figures.js` 파일 내용을 **전체 복사해서 붙여넣고 Enter.**

`준비 완료 → SS.compare()  SS.grid()` 가 뜨면:

```
SS.compare()
```

**다운로드 폴더에 `그림4_하이브리드_비교.png`** 가 저장됩니다. `figures/` 로 옮기고
이름을 `그림5_하이브리드_비교.png` 로 바꾸세요 (④는 음원분리가 이미 씀).

### 5. 확인할 것

- 두 파형의 **높이나 채도가 눈에 띄게 다른가?** 똑같아 보이면 3번으로 돌아가 다른 지점에서 다시.
- 스크립트가 끝나면 **모드가 원래대로 안 돌아옵니다.** 스위치를 눌러 하이브리드로 되돌려 두세요.

### 잘 안 될 때

| 증상 | 원인 | 해결 |
|---|---|---|
| "프레임이 그려지지 않습니다" | 크롬 창이 뒤에 있음 | 창을 맨 앞으로 두고 다시 |
| "2D 대체 렌더러로 돌고 있습니다" | WebGL 컨텍스트가 죽음 | 탭 새로고침 후 다시 분석 |
| "렌더러를 찾지 못했습니다" | 분석 전에 실행함 | 타임라인이 뜬 뒤에 실행 |

**같은 방법으로 `SS.grid()`** 를 실행하면 감정별 파형 4종이 2×2 한 장으로 나옵니다
(포스터의 매핑 설명에 쓰면 좋습니다).

## ③ 화자 전환 대시(—) — 가장 어렵습니다

**먼저 알아두실 것**: 이 기능은 **전 과정 검증을 못 해서 기본값이 꺼져 있습니다.**
포스터에도 "비활성 상태"라고 정직하게 쓰기로 한 부분입니다.
그림은 *"만들어 놨고 이렇게 보인다"* 를 보여 주는 용도입니다.

### 1. 기능 켜기

```bash
/Users/birdhouse/.soundshape_venv/bin/python -c "
import json,pathlib
p=pathlib.Path('config/speaker_config.json'); c=json.loads(p.read_text())
c['enabled']=True; p.write_text(json.dumps(c,ensure_ascii=False,indent=2))
print('화자 구분 켜짐')"
```

**백엔드를 다시 켜야 반영됩니다.** 저에게 말씀하시면 재시작해 드리겠습니다.

### 2. 2인 대화 클립 구하기

여기가 핵심이고, 여기가 어렵습니다. 필요한 조건:

- **두 사람이 번갈아 말하는 실제 영상** (드라마·시트콤 대화 장면)
- **한 사람당 최소 1초 이상** 연속 발화 — 0.5초짜리는 감지 정확도가 0.978 → 0.904 로 떨어집니다
- 배경음악이 너무 크지 않을 것
- 15~30초면 충분합니다

> ⚠️ `data/samples/two_speakers.wav` 는 **쓰지 마세요.** RAVDESS를 이어 붙인 것이라
> 문장이 두 개뿐이고, Whisper 반복 억제가 걸려 구간이 하나로만 잡힙니다.
> 보고서에서 "전 과정 검증 실패"라고 쓴 게 정확히 이 파일 때문입니다.

**추천**: 유튜브에서 대화 장면 20초를 받아 쓰거나, **직접 두 사람이 번갈아 녹음**하세요.
직접 녹음이 제일 확실합니다 — 목소리 차이가 큰 두 사람(예: 남/여)이면 더 잘 잡힙니다.

### 3. 캡처

분석 후 **자막 맨 앞에 `—` 가 붙은 구간**을 찾아 화면을 찍으세요.
대시는 **화자가 바뀐 줄에만** 붙습니다. 연속으로 같은 사람이 말하면 안 붙는 게 정상입니다.

가장 좋은 그림은 **연속된 두 줄**이 보이는 것입니다.

```
   안녕, 오늘 어땠어?
—  그냥 그랬어.
```

### 4. 원상 복구

찍고 나면 **반드시 다시 끄세요.** 검증 안 된 기능이 켜진 채로 시연하면 위험합니다.

```bash
/Users/birdhouse/.soundshape_venv/bin/python -c "
import json,pathlib
p=pathlib.Path('config/speaker_config.json'); c=json.loads(p.read_text())
c['enabled']=False; p.write_text(json.dumps(c,ensure_ascii=False,indent=2))
print('화자 구분 다시 꺼짐')"
```

### 안 되면 이렇게 하세요

**대시가 한 번도 안 붙으면** 억지로 만들지 마세요. 포스터에는 그림 대신
**"표기 예시"를 직접 그린 것**(위 두 줄짜리 텍스트 박스)을 넣고,
캡션에 *"실제 2인 영상 검증 전이므로 표기 예시"* 라고 쓰는 게 정직합니다.
심사에서 이게 훨씬 낫습니다.

## ⑦ 햅틱 밴드 실물 사진 — 부품 도착 후

### 찍을 것 2장

**(1) 부품 연결 사진** — 조립이 얼마나 단순한지가 요점입니다.

- 흰 종이나 밝은 회색 배경 위에 부품을 펼쳐 놓기
- **Qwiic 케이블로 두 보드가 연결된 상태**가 보이게
- USB-C 케이블이 왼쪽으로 빠져나가는 것까지 프레임 안에
- **동전이나 손가락을 같이** 넣어 크기 감각을 주세요 (보드가 25×29mm라 사진만으로는 감이 안 옵니다)
- 위에서 수직으로, 그림자 없이

**(2) 손목 착용 사진** — 실제로 쓸 수 있다는 증거.

- 손목에 벨크로로 감은 상태
- **DA7280 보드(검은 원통이 붙은 빨간 보드)가 손목 안쪽에 닿게**
- USB 선이 노트북으로 이어지는 게 살짝 보이면 좋습니다

### 캡션에 쓸 문구

> ESP32-S3 Feather + DA7280(LRA 모터 일체형). Qwiic 케이블 하나로 연결.
> **납땜 0회 · 배터리 0개.** 브라우저가 Web Serial API로 USB를 통해 직접 통신한다.

### ⚠️ 포스터에 쓸 때

**동작 결과 수치를 넣지 마세요.** 사진이 있어도 측정을 안 했으면 "제작 완료, 측정 예정" 입니다.
블록 전체를 점선 테두리로 두는 규칙은 사진이 들어가도 그대로 유지하세요.
